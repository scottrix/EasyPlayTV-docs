Path & migration log

The addon's storage strategy moved through three distinct phases. This page records the rationale, the technical changes, and what the production DB looks like today.

Phase 1 — .strm files on disk (original)

Originally the addon wrote one .strm file per episode (and per movie) inside addon_data/plugin.video.easyplaytv/Series/ and addon_data/plugin.video.easyplaytv/Movies/. Each .strm file contained a single line:

plugin://plugin.video.easyplaytv/?action=resolve_vod&provider=itvx&episode_id=…

Kodi's video library scanner recursively walked these folders using the TMDb.tv scraper, picked up the .strm files, and treated each as a video file. The scraper created tvshow rows from the parent folder name (e.g. Ackley Bridge), episode rows from each .strm file's parent season folder, etc.

Two problems with this approach drove the migration:

  1. Un-prefixed duplicates. The folder names per show had the bare title (e.g. Ackley Bridge) because Kodi's scraper matches bare titles to TMDb. The addon's own sync engine meanwhile inserted [ITVX] Ackley Bridge-prefixed rows directly into the DB (because the provider matters for episode resolution and showing the user where the show came from). The TMDb scanner kept creating additional un-prefixed rows from the .strm trees on every Kodi boot, conflicting with the prefix rows.
  2. Filesystem churn. A brand-new show from the sync engine meant a new folder + new .strm file on disk; this then triggered Kodi's scanner to re-scrape the entire Series tree. On a Pi SD-card that was ~10 s of I/O per show. With hundreds of new shows per sync, the library browser was unusable for 15+ minutes after every sync.

Phase 2 — plugin:// URL insertion + exclude=1 on the path row

The current design. The addon:

  1. Stops writing .strm files entirely. The filesystem is now flat (just one addon profile dir).
  2. Inserts the plugin://… URL directly into the files table under a single plugin://plugin.video.easyplaytv/ path row (idPath=485 — the same single path row every episode/movie is attached to).
  3. Sets exclude=1 on the plugin source path row via library_sync.ensure_series_path_config. This stops Kodi's TMDB scanner from automagically creating duplicate tvshow rows when it sees the plugin URL in the path table — see the warning in ensure_series_path_config.
  4. Inserts the [PROVIDER] Title-prefixed display title directly into tvshow.c00 (via library_sync._insert_tvshow) and movie.c00 (via _insert_movie), bypassing the scraper entirely.

The migration itself — migrate_to_plugin_paths()

Called once from service.py on startup (master mode only). Idempotent — does nothing once migration is complete.

Steps (full detail in library_sync.migrate_to_plugin_paths):

  1. _repair_scraper_path_settings(db) — re-quotes unquoted XML attributes in legacy path.strSettings rows and forces verboselog=false. (Earlier versions of the addon had propagated an unquoted XML with verboselog=true into EasyPlayTV path rows — caused ~22s per TMDb season API call's log pformat on RPi SD I/O, ~13 min for WWE Raw alone — that was the original motivation for _sanitize_scraper_settings_xml.)
  2. Insert the single PLUGIN_SOURCE_PATH path row if it doesn't already exist (with exclude=0 at this stage; ensure_series_path_config later flips it to 1).
  3. For every episode row joined to a legacy disk path matching %easyplaytv%…/Series/%…/.strm: read the .strm file to get the saved plugin://… URL (or scan sibling files if the exact file isn't there but a SNEN-pattern sibling is), parse out the query-string, write a NEW files row under PLUGIN_SOURCE_PATH with the query-string as strFilename, UPDATE episode.idFile and episode.c18 to point at the new file row, DELETE the old file row. Logged as "Migrating N episode path entries" at line 1656.
  4. Same for movies — also re-inserts the videoversion row Kodi 21 expects (line 1743-1747 — Kodi 21 won't show a movie in the UI without a videoversion row).
  5. For every distinct tvshowlinkpath on a legacy disk Series path: record the idShows, DELETE all the old tvshowlinkpath rows, UPDATE path SET exclude=1 on every orphan disk-folder path (line 1773-1777) to stop Kodi's scanner from re-attaching to them on boot. Re-link every show to PLUGIN_SOURCE_PATH via INSERT IGNORE INTO tvshowlinkpath.

Restart Kodi after first run

The addon can run the migration while Kodi is live, but Kodi's video window caches the old path/shows in memory for the lifetime of the current session. After the first migration completes, the user should restart Kodi so the in-memory cache is dropped and the new PLUGIN_SOURCE_PATH-attached rows are what Kodi sees. The UpdateLibrary(video, ...) builtin that sync_provider fires does most of the refresh but isn't a full memory clear.

Known dead code from the migration (clean-up opportunities)

  • strm.py:STRM_MOVIES_DIR / STRM_SERIES_DIR / STATE_FILE — defined but unused.
  • library_sync.py:MOVIE_PATH / SERIES_PATH plus the redundant STRM_MOVIES_DIR / STRM_SERIES_DIR constants — still used by query substrings in prefix_existing_* functions; deleting would require updating those LIKE clauses to a regex on the existing PLUGIN_SOURCE_PATH-only path-row idPath.
  • movies_db._load_strm_providers() and its _strm_provider_cache / _strm_epid_cache — walks an empty directory, returns {}. Still called by get_provider_for_title and get_movies's plugin-filename fallback (the latter can be removed — the plugin URL is in movie.c22 now).
  • movies_db._provider_from_strm — reads a non-existent file; returns "". Safe to remove.
  • library_sync._insert_episode's open(strm_path) at lines 1119-1126 — kept for back-compat with the hypothetical case a .strm path is ever passed in; in practice the sync passes empty and uses the c18 fallback. Safe to remove.
