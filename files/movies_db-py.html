resources/lib/movies_db.py — Kodi movie library queries

Path /resources/lib/movies_db.py Lines 389 Type read-side queries (Kodi DB) — drives list_movies UI ← called by default.py:list_movies / list_movie_genres → calls pymysql — reuses connection-config helpers from library_sync

Role

The UI's read-side mirror of library_sync.py's movie writes. Where library_sync inserts/updates movie rows via direct SQL, this module reads them back via SQL and builds Kodi ListItem objects via movie_to_listitem.

Dead / legacy code — _load_strm_providers

_load_strm_providers() · line 43

Walks MOVIE_PATH for .strm files, builds a {safe_filename: provider} dict, and an episode-id → file-path map. Since the addon deleted all .strm files in the path-migration cleanup (see migration log), this function reads an empty directory and returns {} via the os.path.getmtime() OSError catch (line 47). It's dead code effectively but still called by get_provider_for_title and get_movies's plugin-filename fallback. Should be removed in a refactor.

Module-level single-connection cache (_db). The base movie query

_base_movie_query() · line 143

The shared SELECT-backbone. Notable bits:

  • The inner SELECT … GROUP BY c00 subquery deduplicates movies that have the same c00 (display title). Picks "best_id": if any variant has c22 LIKE '%.strm' prefer the .strm-attached one (legacy native files), else the highest idMovie. The post-migration plugin-URL rows have c22 LIKE 'plugin://%' so this de-dup logic still picks the right row when there are legacy .strm-rows left over — though there shouldn't be any in production now.
  • LEFT JOINs on art twice — once for poster, once for fanart — so the UI gets the image URLs in a single query.

get_movies(genre=None, offset=0, limit=40) → tuple[list[dict], total_count] · line 181

The main UI browse query. Adds a genre filter and pagination when supplied. Each movie dict passed to the UI builder has fields including title, plot, genres, thumb, fanart, file, provider_url, strm_key. The interesting bit is the provider_url/strm_key derivation at lines 217-231: plugin-URL-attached movies get a provider_url (the full plugin://… playback URL — Kodi will use this for play); disk-attached movies get a strm_key (the filename without .strm) — used as a dict key for the legacy _strm_provider_cache fallback path.

movie_to_listitem(movie) · line 340

Wraps a movies dict (as returned by get_movies) in a Kodi ListItem with all the expected setInfo props (title, plot, rating, year, runtime, genres, director, cast, tagline, mpaa). Sets up the play URL via build_url(action='play_strm', strm_path=…) or build_url(action='resolve_vod', provider=…, episode_id=…) depending on whether the row came from the plugin-path mode (provider_url set) or the legacy strm-path mode (strm_key set).
