default.py — plugin entry point & router

Path /default.py Lines 1,337 Type python.pluginsource (Kodi-invoked) Stateless? yes — re-imported per call ← invoked by Kodi (one fresh interpreter per call)

Role

The Kodi plugin entry-point. Kodi launches a new Python interpreter, runs this script with sys.argv shaped like ["plugin://plugin.video.easyplaytv/", handle, "?mode=…&action=…"], and expects the script to either populate the directory listing for handle (with xbmcplugin.addDirectoryItems) or hand back a playable ListItem (resolved by the chosen inputstream.adaptive DASH item).

The script itself is one big dispatch table — it pulls a routing key out of the query string then calls the matching list_* / resolve_* helper. Everything substantive lives in resources/lib/; this file just routes.

Module-level constants

Standard Kodi plugin boilerplate, lines 3–5. BASE_URL is the plugin:// URL Kodi invoked us under; HANDLE is the integer directory handle your addDirectoryItem calls must target; _ADDON is the cached xbmcaddon.Addon("plugin.video.easyplaytv") used everywhere to read settings.

Two-tier caching. Live-TV listings cache for 10 min on disk under resources/cache/ (shipped with the addon). VOD catalogue caches for 6 h to match the service's sync cadence — see library_sync.py. Cache files are named vod_.json.

_resolve_channel(resolver_module, resolver_fn, channel_id, channel_name) · line 117

Wraps "import the provider module, call its resolver, set up DASH, resolve the ListItem". Short-circuits with a notification if BBC is selected and has_tv_license is false (line 119). Calls setup_dash_item() with the manifest + license data returned by the provider.

resolve must not swallow the manifest URL

The resolver returns a tuple of (manifest_url, license_url, headers, payload, …); the caller passes all of it onward as kwargs. If you add a new provider here, be sure its resolver actually returns a manifest URL (not a top-level M3U8 to be played natively) — only DASH via inputstream.adaptive is supported.

The dispatch table (lines ~1196–1337)

The if __name__ == "__main__" block (currently a long action == '…' / elif action == '…' chain, with an extra mode == '…' chain for directory-listing routes) is the only place where Kodi's argv gets mapped to a function. Two routing keys are used:

KeyPurposeExamples
action=One-shot verbs (resolve, sync, login, logout, backfill_art, prefix_titles, play_strm)resolve_live, resolve_vod, itvx_login, sync, backfill_art
mode=Directory listings — Kodi opens a folderlive_tv, movies, series, vod_shows, vod_seasons, vod_episodes_db
Cache-to-disc caveat for sync via JSON-RPC

Lines 1288–92 explicitly call xbmcplugin.endOfDirectory(HANDLE, succeeded=False, cacheToDisc=False) when triggering ?action=sync&provider=…. Without this, Kodi's CGUIMediaWindow treats the URL as the current folder and re-fetches it on the 7-minute auto-refresh — which would re-fire the sync every 7 min.

Sync has two modes

If ?action=sync&blocking=1 the sync runs in the calling thread (so the script interpreter stays alive until completion — needed when firing via JSON-RPC RunPlugin). Without blocking=1 it spawns a daemon thread and returns immediately. Daemon threads die when the calling script returns, so fire-and-forget only works from within Kodi's UI navigation; from JSON-RPC you must use blocking=1 or use the marker-file mechanism in service.py instead.
