resources/lib/itvx_vod.py — ITVX catalogue

Path /resources/lib/itvx_vod.py Lines 373 Type catalogue scraper (Next.js __NEXT_DATA__ JSON + session cookies) ← called by strm._fetch_*, library_sync.sync_series_direct → calls www.itv.com Next.js-rendered HTML pages, ITVX's same auth/cookie session used by itvx.py

Role

Scrapes ITVX's server-rendered React pages (Next.js). Each page embeds a JSON blob inside — the same JSON Next.js uses to hydrate the client. Parses that JSON into the addon's show/season/episode dict shape.

Listing functions

Static return from CATEGORIES. Could call the live site's /categories endpoint but ITVX's category page doesn't surface the list-with-counts at the API level we use; the static list is simpler and rarely changes.

list_shows(category_id) · line 228

Fetches https://www.itv.com/watch/categories/, parses __NEXT_DATA__, walks data["props"]["pageProps"]["..."]["titles"]. Each title dict has id (the production_id), title, slug (programme URL slug), imageUr ls, and — importantly — standalone (true if "playable" one-off, false if multi-episode series). The addon's strm._fetch_series_shows uses standalone + episode_id to decide _nav_mode.

list_episodes(programme_slug, programme_id) · line 285

Fetches https://www.itv.com/watch/ and parses episodes from the same Next.js blob. programme_id is used to filter titles when the URL doesn't itself identify the show (multi-show anchor pages). The returned episode dicts include both episode_id (the production_id of THIS episode, used by itvx.resolve_vod) and a playlist_url (the canonical playlist URL for this specific episode; passed through to the resolver to short-circuit version retry).

Pagination

ITVX's catalogue page doesn't paginate at the URL level — every show for a genre returns in one __NEXT_DATA__ blob. This works fine for small genres (Comedy, News) but the Drama page is ~2MB and the page may slightly increase startup time on a cold cache. Caching handled at the default.py layer via VOD_CACHE_TTL.
