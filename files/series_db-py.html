Role

Series counterpart of movies_db.py. Drives the addon's TV-show browse UI (list_vod_shows, list_vod_provider_shows, list_vod_seasons_db, list_vod_episodes_db). All reads come from Kodi's video DB — no live HTTP fetches — which is why series browsing is fast even with 6,114 shows and 128K episodes.

EPTV-show-identification helpers

_series_path_like() = "%easyplaytv%Series%" · _eptv_show_ids_sql() / _eptv_show_ids_params() · lines 80, 84, 98

The trick to identifying "this tvshow belongs to EasyPlayTV". Because the addon neither stores its shows in a unique DB column nor tags them, the queries pattern-match on the path row attached to each show via tvshowlinkpath. The SQL returned by _eptv_show_ids_sql is a UNION of:

  • shows attached (via tvshowlinkpath) to a path row matching %easyplaytv%Series% OR the plugin source path (plugin://plugin.video.easyplaytv/);
  • shows attached (via episode → files → path) to the same

The latter catches shows that for some reason lost their tvshowlinkpath row but still have episodes pointing at EasyPlayTV paths.

get_series(genre=None, offset=0, limit=25, letter=None) → tuple[list[dict], total] · line 204

Heavyweight main query. Always filters to EasyPlayTV-attached shows via the _eptv_show_ids_sql subselect; restrictions on genre (join on genre_link + genre.name) and letter (REGEXP-stripped c00 LIKE) stack on top. Orders by REGEXP-stripped c00 — so "[ITVX] Ackley Bridge" sorts under A, not I.

C00 sort key regex

EveryWHERE we sort by display title, we strip the [PROVIDER] prefix via REGEXP_REPLACE(c00, '^\\[[^\\]]+\\]\\s*', ''). If this regex breaks (e.g. MariaDB drops regex_replace in some odd future build), the entire UI shows shows sorted by provider tag — UX catastrophe. Worth checking on a Kodi upgrade that bumps the DB schema.

Per-show season listing. Returns season dicts with id, season_number, name, poster, fanart, idShow. Dedup: a season can appear under multiple paths (legacy disk path + plugin source path) — the seen_seasons dict in lines 372+ collapses duplicates and chooses the row with the most recent episode count. This is one of the functions most affected by the path migration's residual data:

Legacy duplication still happening

If a show has seasons visible under BOTH a legacy disk path AND the plugin source path (the migration may have re-linked the show but left seasons attached to old paths), the dedup logic at line 372+ kicks in. It picks the "best" path by counting episodes per path. The same logic also handles a path-migration edge case where some leftover path rows haven't been excluded=1'd yet — see the library_sync.migrate_to_plugin_paths UPDATE path … exclude=1 step.
