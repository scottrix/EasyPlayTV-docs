resources/lib/library_sync.py — the sync engine

Path /resources/lib/library_sync.py Lines 1,789 Type sync engine (called by service.py + default.py) ← called by service.py, default.py (manual sync, backfill_art, prefix_titles) → calls pymysql, TMDb HTTP, all *_vod.py providers, strm.py

Role

The heart of the addon. Connects to Kodi's MariaDB video database (MyVideos131 at 192.168.178.17:3306), fetches catalogue listings from each provider, enriches them with TMDb metadata, and writes tvshow / seasons / episode / files / movie / uniqueid / art rows directly — bypassing Kodi's own scanner. After each successful sync it fires a targeted UpdateLibrary(video, …) builtin so Kodi's window refreshes without re-scraping.

DB connection model — the gotcha

_get_db() -> pymysql.Connection · line 52

Per-thread connection cache. Each worker thread (one per provider in service.py) gets its own pymysql.connect() stored on the thread-local. The main thread falls back to the module-level _sync_db for back-compat with non-threaded GUI callers.

pymysql is NOT thread-safe on a shared connection

Concurrent queries on the same socket corrupt each other's MySQL packet stream. Two failure modes observed in production:

  • "Packet sequence number wrong - got 2 expected 1" — packets from two threads interleave on the wire.
  • "'NoneType' object has no attribute 'read'" — one thread's ping() closed the other's socket reader mid-query.

The original fallback that wrapped a failed ping with a re-create also grabbed _sync_db for non-main threads, so when a worker's connection died mid-query it would silently hop onto the main thread's socket and re-corrupt. The current code at line 74-88 explicitly checks threading.current_thread() is threading.main_thread() before touching _sync_db — workers always create their own.

_read_db_config() -> dict | None · _resolve_db_name(cfg) -> str · lines 110, 131

This lets the addon survive a Kodi upgrade that bumps the schema (e.g. MyVideos131 → MyVideos132) without code changes.

ensure_series_path_config() · line 212 — for series

Same idempotent insert-or-update for PLUGIN_SOURCE_PATH, but sets exclude=1. Reasoning (from the inline doc):

Why the plugin URL is exclude=1

Registering the plugin URL as a strContent='tvshows' path with exclude=0 causes Kodi's library scanner to scrape the addon's directory listings and create tvshow rows on its own. Because the addon's Series-mode listing returns provider-flavoured show titles like "Ackley Bridge" (without the DB-prefixed [ITVX] Ackley Bridge convention), Kodi's TMDb.tv scraper created hundreds of un-prefixed 0-episode duplicate tvshow rows that conflict with the prefixed rows directly inserted by sync. Keeping the path row (so tvshowlinkpath can attach to it) but setting exclude=1 stops Kodi's scanner from recursing into the plugin URL. The addon fills the library via direct INSERTs; Kodi's scan is unwanted noise.

The big show: sync_series_direct

sync_series_direct(force=False, provider_filter=None) -> int · line 667

The spine of the addon. Steps:

  1. ensure_series_path_config() — make sure the plugin:// path row exists with exclude=1.
  2. Import and call strm._fetch_series_shows() to get every show from every provider.
  3. If provider_filter is set, restrict to that provider (so manual per-provider syncs in service.py don't re-process all 7000+ other-provider shows each time).
  4. Query existing tvshow rows on PLUGIN_SOURCE_PATH and build two sets: existing_safe_titles (anything) and existing_safe_titles_with_eps (any show with ≥1 episode). Pre-strip the [PROVIDER] prefix so prefixed and un-prefixed rows collapse to the same key — this is the de-duplication safety net.
  5. For each show:
  6. a. Skip if safe_title in existing_safe_titles_with_eps (unless force=True).
  7. b. TMDb search → TMDb TV fetch for canonical metadata.
  8. c. Fetch episodes BEFORE inserting the tvshow row. This avoids a class of bug where inserting first then skipping on if not episodes: continue would leak empty tvshow rows into the DB (films mis-badged as series, withdrawn brands, API fetch errors). Fetchers all key off the show's own fields (f_name/pid/slug) so they don't need show_id.
  9. d. Provider-specific episode fetcher dispatch (BBC / My5 / ITVX / C4 / STV — the five providers that expose series).
  10. e. STV episode_number=0 renumbering pre-pass (lines 858–888). Some providers (notably STV) return episodes with episode_number=0 when playerSeries is null. The insert loop drops episode_number=0 via if en_int < 1: continue, which would otherwise drop single-episode documentaries and entire programmes without per-episode index info (Coronation Street, Emmerdale daily strips). The renumber pre-pass re-numbers them sequentially from 1 within their season block, preserving explicit numbering for the episodes that do have a number. If season is also 0/missing, it's bumped to 1 so the show appears as Season 1 rather than the Kodi specials block (S00).
  11. f. _insert_tvshow(db, safe_title, tv_data, provider=…).
  12. g. For each episode: build strm_url, parse sn_int/en_int (defaulting missing/zero seasons to 1, but dropping zero episode numbers), _ensure_season(), then _insert_episode(db, show_id, season_id, sn, en, ep_data, strm_url, "", show_name=…). ep_data comes from the TMDb season-cache keyed by (sn_int, en_int) — so episode titles/plots/thumbs are TMDb's, not the provider's.
  13. h. Persist state to series_sync_state.json every 5 shows; sleep 1 s every 20 shows (TMDb rate-limit politeness).
Don't override the sync's provider from provider_map

Lines 826-838 have an explicit warning inline. provider_map stores the first provider that synced a given safe_title — e.g. an ITVX run populated provider_map["Buried"]["provider"]="itvx". When C4 later syncs its own "Buried" (provider="c4" from c4_vod.list_shows), an override would silently switch provider to "itvx" and then the episode fetcher would call itvx_vod.list_episodes with C4's empty _nav_slug/_nav_prog_id — producing 404s and zero episodes inserted. The show dict's provider is authoritative for the sync in progress; provider_map is used only for UI cross-refs.

Fix — fetch-first ordering

Fetching episodes before the tvshow INSERT eliminated several hundred empty-show rows in the production DB. If you see empty shows in the library today, look for a provider whose list_episodes raised an exception and let it bubble — don't try to fix it by inserting the tvshow first.

_insert_tvshow(db, show_dir, tv_data, provider="") · line 999 · returns (show_id, is_new)

The single most subtle function in the addon. Two prefix candidates:

  • prefixed_name — built from TMDb's canonical name (tv_data["name"]).
  • prefixed_dirname — built from show_dir (the local safe_filename(show_title)).

Lookup preference: prefixed_dirname first, then prefixed_name. This is critical because TMDb's Search-by-title can re-rank similar-named siblings — e.g. C4's "Buried" → TMDb returns "Buried Hearts" with a different tmdb_id. If we keyed purely on TMDb's canonical name, every subsequent sync would resolve the title to "Buried Hearts", insert a fresh tvshow row, and orphan the original "[C4] Buried" row — its idShow ends up empty forever because every episode rows' idShow points at the new row.

TV show lookup must prefer prefixed_dirname first

The primary lookup must be the show_dir-based name (prefixed_dirname) before the TMDb canonical name (prefixed_name). TMDb search re-ranks titles dynamically — when "Buried" is searched one day it can resolve to "Buried Hearts" and the next day to "Buried" (different shows). If we keyed off prefixed_name we would fragment a show's episodes across two tvshow rows over successive syncs. Keying off prefixed_dirname keeps the local show identity stable across re-ranks.

Besides the lookup order, this function also:

  • Assembles the all-important c10 ({"tmdb":"…","imdb":"…","tvdb":"…"}) JSON — required by Kodi's VideoInfoScanner before it'll call the scraper's GetEpisodeList. Kodi ignores the tvshow row's own idShow for episode enrichment; it reads the episodeguide from c10. If empty, episodes won't be fetched by Kodi, even though our own sync inserts episodes directly (this field still matters for the rare cases where Kodi tries to scan).
  • Inserts into tvshow, tvshowlinkpath, uniqueid (tmdb + imdb + tvdb), genre_link, and art (poster + fanart).
c10 wrapper tags — why we emit

Kodi's own VideoInfoScanner writes c10 in the wrapped form {"tmdb":"…"}, and Kodi's scraper code accepts both bare JSON and the wrapped form. We emit the wrapped form so addon-inserted rows have the same shape as Kodi-scraped rows when both coexist in the library — e.g. an Optima disk-source row next to a BBC plugin-source row in the same Kodi view.

Pre-existing bare-JSON rows written by older addon builds (about 6,000 on the production box) are not rewritten on sync — Kodi still reads them fine, so they're left untouched. Only freshly-inserted shows pick up the wrapped form.

_insert_episode(db, show_id, season_id, season_num, ep_num, ep_data, strm_path, strm_filename, show_name="") · line 1118

Inserts a single episode. Idempotency check at line 1114 by (idShow, c12=season, c13=episode) triple. Builds ep_c00 as "Show Name - Episode Title" when different, just like Kodi's own scraper does. Inserts into files (with the full plugin URL as strFilename — see below), episode, uniqueid (tmdb episode id), art (still thumbnail).

strFilename holds the full plugin URL — same string as episode.c18

For every row the addon writes, files.strFilename is set to the full plugin://plugin.video.easyplaytv/?action=resolve_vod&provider=…&episode_id=… URL — the same string that goes into episode.c18. There's no ?-only truncation; the addon's _insert_episode at line 1136 simply aliases plugin_filename = strm_url and inserts that into both columns. This differs from how Kodi's own scanner populates disk-based rows, where strFilename is the bare basename (e.g. S01E01 - 12AM-1AM.mkv) and c18 is the full http://…/Season 1/S01E01 - 12AM-1AM.mkv.

Practical consequence: when Kodi's library window renders an EasyPlayTV episode row, the filename column shows the raw plugin://...?action=resolve_vod&... URL rather than a pretty basename. The skin's ListItem.Label falls back to episode.c00 (the display title) so the user sees "Doctor Who - Into the Dalek" in the title column, not the URL — but if a skin falls back to the filename for an empty-title row, the URL will leak through.

Run via ?action=prefix_titles in default.py. Retrofits the [PROVIDER] Title prefix onto rows that pre-date the convention (e.g. rows inserted before the provider label was being written into c00). prefix_existing_tvshows has a 3-tier matching strategy against provider_map:

The entry point

sync_provider(provider, force=False) · line 1555

The function service.py calls. Branches:

  • If provider is given (the normal case from service.py): call sync_series_direct(force=force, provider_filter=provider).
  • If provider is empty (the unsynced "sync everything" path, not normally used by service.py which always passes one provider): remove_stale_movies(), remove_stale_series(), sync_movies_direct(), sync_series_direct(force=force).
  • Always: prefix_existing_tvshows(), fix_sort_titles(), then xbmc.executebuiltin('UpdateLibrary(video, "/home/osmc/.kodi/userdata/addon_data/plugin.video.easyplaytv/")').
  • The UpdateLibrary call is targeted on the EasyPlayTV profile root so Kodi re-scans only our plugin-source path (and any un-excluded disk folders), not the entire library — avoids reviving TMDb scraper runs across unrelated sources on every 6h sync.
  • Pops a Kodi notification: "Sync done: +N movies, +N series."

migrate_to_plugin_paths() · line 1625

Called by service.py on every startup (master mode only). Idempotent — on a fully-migrated DB every SELECT inside returns zero rows and it exits cleanly.

Why it's still called on every startup (not just once): the addon can be re-installed, the DB can be restored from a snapshot, or a stale Kodi scanner run can sneak disk-folder rows back in. Running this on every startup guarantees the invariant — emerald-clean DB, all episodes and movies attached to PLUGIN_SOURCE_PATH, exclude=1 on every disk-folder path row — is re-established within a few seconds of boot no matter what state the DB is in.

Steps (each is a no-op if the DB is already in the target state):

  1. Run _repair_scraper_path_settings.
  2. Insert the PLUGIN_SOURCE_PATH path row if missing (exclude=0 at this stage — ensure_series_path_config later flips it to 1).
  3. For every episode row joined to a files row on a disk path matching %easyplaytv%…/Series/%…/.strm, read the .strm file (or scan sibling files for an SNEN regex match), parse out the plugin://…?… URL, write a new files row under PLUGIN_SOURCE_PATH with the query-string as strFilename, UPDATE episode.idFile and episode.c18, delete the old file_id.
  4. Same for movies — also rewrites movie.idFile and re-inserts the videoversion row that Kodi 21 expects.
  5. For every distinct tvshowlinkpath on a disk path, record the idShows, DELETE all the old tvshowlinkpath rows, then UPDATE path SET exclude=1 WHERE strPath LIKE …/Series/% (lines 1773-1777) to keep Kodi's scanner off the per-season disk-folder rows. Without this, the disk folders would be re-attached to the scanner on every Kodi boot, undoing the direct-write design.
  6. Re-link every show to PLUGIN_SOURCE_PATH via INSERT IGNORE INTO tvshowlinkpath.
Idempotent by design

Safe to call on every service startup. Every UPDATE / INSERT is guarded by a SELECT or uses INSERT IGNORE, so a clean DB takes the no-op path through the function; the "Migrating 0 episode path entries" / "Migrating 0 movie path entries" log lines are expected and indicate the invariant is held.
